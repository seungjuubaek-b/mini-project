사용자는 성인을 대상으로 일상 글의 이해와 생각 정리를 함께 돕는 서비스를 승인했으며 실제 생성 기능에는 OpenAI API를 사용한다고 확인했다. 기존 `ideation-worksheet2.md`, `prd-auto-healing2.md`는 별도 주제의 문서로 보존한다. 이전 서비스의 인원·수치·복구 정책은 이어받지 않는다. 아래에서 확인된 내용, 설계 제안, 미결정 사항을 구분한다.

사용자는 이후 이 문서 말미의 추가 정책으로 PRD 초안을 작성하는 데 동의했다. 아래 역할의 ‘제안’은 그 검토 과정을 기록한 표현이며, 시간·횟수·저장·검증의 현재 기준은 말미의 확인된 정책 표와 [PRD 0.1](prd-auto-healing.md)을 따른다. API 모델·예산과 개발 인원은 계속 미정이다.

# 1. 서비스 선정

## 1.1 어떤 서비스의 장애를 자동 복구할 것인가?

**서비스 이름:** 성인을 위한 일상 글 이해·생각 정리 도우미 (가칭).

**한 문장 설명:** 성인 사용자가 이해하기 어려운 생활 글을 입력하면, 서비스는 OpenAI API를 통해 쉬운 설명과 핵심 내용, 생각 질문을 제공하고 힌트와 근거 설명으로 사용자의 생각 정리를 돕는다.

**정상 실행 흐름:**

```text
성인 사용자 → 생활 글 입력·도움 요청 → 글 이해·생각 정리 API
→ 설명·질문 생성 서비스 → OpenAI API
→ 쉬운 설명·핵심 정리·생각 질문 → 선택적 힌트·사용자 답변의 근거 확인
```

입력 예시는 생활 안내문·공지·문자 등이다. 실제 개인의 메시지를 수집하는 실습 대신 가상 생활 글을 사용한다. 사용자는 답변 연습을 건너뛸 수 있도록 하는 방안을 제안한다. 진단 여부를 가입·사용 조건으로 요구하지 않는다.

**핵심 의존 서비스:**

| 의존 대상 | 용도 | 실패 시 영향 | 모의 구현 여부 |
|---|---|---|---|
| OpenAI API | 실제 쉬운 설명·핵심 정리·질문·피드백 생성 | 설명 불가·응답 지연 | 정상 기능은 실제 사용, 외부 서비스 자체 조작 금지 |
| 실습용 설명 생성 서비스 | 외부 생성 요청과 결과 전달의 경계 | 핵심 API가 생성 결과를 받지 못함 | 장애 실험 시 모의 응답·오류·지연 제공, 로컬 대상만 중단 |

실습용 생성 서비스 분리는 승인된 장애 실험을 구체화하기 위한 개념 설계다. 세부 실행 형태는 [미결정]이다.

## 1.2 서비스가 멈추면 어떤 영향이 발생하는가?

- 사용자 영향: 글 이해·질문 연습이 끊기고 다음 행동을 정리하지 못할 수 있다. 실패를 사용자의 능력 탓으로 표현하지 않는다.
- 운영 영향: 오류와 호출 상태를 확인하고 재시도 가능성·지속 장애·비용 발생 여부를 판단해야 한다.
- 데이터·비용·보안 영향: 입력 글이 외부 API로 전송되며 반복 호출은 비용을 늘릴 수 있다. 실습에서는 가상 글을 사용하고 키·원문을 로그에 남기지 않는 방안을 제안한다. 실제 제품의 저장·전송 정책은 [미결정]이다.
- 심각도 제안: 중간. 핵심 도움 기능이 중단된다. 의료·법률 등 전문 판단이나 긴급 대응은 MVP 범위 밖이다.

## 1.3 현재 사람은 장애를 어떻게 발견하고 복구하는가?

실제 운영 시스템·장애 대응 경험은 확인되지 않았다. 다음은 비교용 수동 대응 제안이며 기존 운영 사실이 아니다.

| 단계 | 비교용 수동 행동 | 정보·도구 | 실제 소요시간 | 예상 문제점 |
|---|---|---|---|---|
| 탐지 | 결과가 안 나오는지 확인 | 오류·응답시간 | [미결정] | 장애 확인 지연 |
| 진단 | 외부 오류와 로컬 중단 구분 | 응답·실행 상태 | [미결정] | 원인 오진 |
| 복구 | 재요청 또는 확인된 로컬 대상 재시작 | 제한된 호출·관리 기능 | [미결정] | 중복 요청·비용 증가 |
| 검증 | 사용자 경로로 결과 확인 | 필수 항목·기준 글 | [미결정] | 응답 성공을 정확성으로 오해 |
| 보고 | 근거·시도 정리 | 사건 이력 | [미결정] | 누락·원문 노출 |

**자동화하려는 단계:** 탐지, 증거 기반 분류, 제한된 복구, 독립 동작 검증, 결과 기록.

**사람이 담당할 단계:** 설명 품질 검토, 원인 불명·지속 장애 조사, 비용·정책 변경, 자동 조치 재개 판단.

## 1.4 3일 동안 재현 가능한 최소 서비스는 무엇인가?

**포함 (사용자 확인 완료):** 간단한 웹 화면에서 짧은 생활 글 하나 입력 → 쉬운 설명·핵심 정리 → 생각 질문 1개 → 힌트·답변 피드백 한 번. 세 장애의 복구·독립 검증·이력도 포함한다.

**제외:** 사진·음성·파일 업로드, 장기 자유 대화, 진단·능력 점수·치료 효과 판정, 아동용 콘텐츠, 실제 개인정보 저장, 전문 의료·법률 판단.

**확인된 여건:** Python·FastAPI·Docker·AWS 사용 경험, 학원 제공 Windows 노트북. 로컬의 간단한 웹 화면을 기준으로 한다. Docker 등 구체 실행 구성·실행 가능 여부·개발 인원은 [미결정]. OpenAI API 사용은 확정됐으며 모델·호출 예산은 [미결정]. 실제 유료 호출 전 모델·호출·비용 상한을 정한다.

**선택 장애:** 모의 HTTP 5xx, 모의 응답 지연·타임아웃, 실습용 생성 서비스 중단. 지속·반복 장애에 대한 안전 중단도 검토한다.

# 2. 에이전트 설계

다음 역할은 개념 설계 제안이다. 실제 설명·질문에는 생성 모델을 사용하지만 장애 탐지·한도 관리는 규칙으로 처리할 수 있다. 인원 수나 별도 LLM 수와 역할 수를 동일시하지 않는다.

## 2.1 장애를 탐지하는 주체는 누구인가?

**이름:** Monitor.  
**관찰:** 생성 요청 오류, 경과시간, 연결 상태.  
**판정 조건:** 요청 중 5xx·연결 실패·모드별 시간 초과 관찰. 실제 시도 30초, 모의 시도 2초 제한. 정기 유료 호출 점검은 하지 않으며 별도 MTTD 수치 목표는 두지 않는다.  
**출력:** 사건 식별자, 대상, 오류 분류, 탐지 시각과 근거. 반복 관찰만으로 새 유료 호출을 무제한 발생시키지 않는다.

## 2.2 원인을 진단하는 주체는 누구인가?

**이름:** Diagnosis. **입력:** 사건·응답 증거·로컬 대상 실행 상태.

| 장애 | 판단 근거 | 제안 규칙 |
|---|---|---|
| 5xx | 생성 의존 서비스 오류 응답 | 재시도 가능한 일시 오류 후보 |
| 타임아웃 | 정한 응답 한도 초과 | 응답 지연으로 분류, 실제 호출 완료 여부는 단정하지 않음 |
| 로컬 중단 | 연결 실패와 허용 대상 중단 확인 | 두 근거가 있을 때만 재시작 후보 |
| 원인 불명 | 연결 실패이나 대상 실행 중·상태 불명 | 자동 변경 중단·운영자 전달 |

인증·사용 한도·요금 관련 오류의 구체 분류는 후속 공식 문서 확인과 정책 결정 대상이다. 모든 오류를 같은 재시도 대상으로 처리하지 않는다.

## 2.3 복구를 실행하는 주체는 누구인가?

**이름:** Recovery.  
**허용 제안:** 정책·예산 한도 안의 재시도, 중단이 확인된 지정 로컬 생성 서비스 재시작.  
**금지:** OpenAI 외부 인프라 재시작, 임의 명령, 자동 결제·예산 증액·키 변경, 입력 글 변조, 설명 오류를 숨긴 성공 반환.  
**필요 기능:** 제한된 생성 호출과 지정 로컬 대상 상태 조회·재시작. 구체 명령은 작성하지 않는다.

## 2.4 복구 성공을 독립적으로 검증하는 주체는 누구인가?

**이름:** Verification.  
**이유:** 요청 성공이나 재시작 완료가 실제 설명 기능의 회복을 보장하지 않는다.  
**동작 검증 제안:** 사용자 경로로 기준 글을 처리해 쉬운 설명·핵심·질문 항목이 비어 있지 않고 정한 시간 안에 반환되는지 확인한다.  
**실패 조건:** 요청 실패·시간 초과·필수 항목 누락. 독립 기준 요청 1회, 실제 30초·모의 2초 한도이며 실패 시 추가 유료 재생성 없이 회로를 연다.

설명의 사실성·쉬운 정도·질문의 적절성은 별도 기준 글과 사람의 검토로 평가한다. 필수 항목이 있다고 정확한 설명으로 판정하지 않는다. 실제 API는 정해진 예산 내 품질 확인, 모의 서비스는 반복 장애 재현에 사용하고 결과를 구분한다.

## 2.5 오케스트레이터가 필요한가?

**제안:** 필요. 사건 상태·호출 순서·재시도·전체 시간·예산 한도를 일관되게 관리한다. 한도를 우회하거나 직접 외부 인프라를 조작하지 않는다. 비용과 중복 호출을 고려해야 하므로 복구 역할과 통제 책임을 분리한다.

## 2.6 에이전트 협업 구조

| 역할 | 입력 | 출력 | 호출 주체 | 허용 권한 | 타임아웃 |
|---|---|---|---|---|---|
| Monitor | 오류·응답시간 | 사건·근거 | 요청 관찰 흐름 | 관찰·사건 생성 | 실제 30초·모의 2초 요청 제한 |
| Diagnosis | 사건·실행 상태 | 분류·복구 방향 | Orchestrator | 증거 읽기 | 사건 전체 한도 내 |
| Recovery | 정책·남은 한도 | 시도 결과 | Orchestrator | 제한 호출·허용 로컬 재시작 | 실제 30초·모의 2초, 재시작 준비 10초 |
| Verification | 기준 글·필수 항목 | 독립 검증 결과 | Orchestrator | 기준 요청·결과 확인 | 실제 30초·모의 2초, 1회 |
| Notification | 상태·근거 | 운영자 확인 정보 | Orchestrator | 로컬 상태 화면·로그 표시 | 외부 전송 대기 없음 |
| Orchestrator | 사건·역할 결과 | 상태·중단·전달 | 사건 처리 흐름 | 역할 호출·한도 관리 | 탐지 후 전체 90초 |

```text
생성 요청 이상 → 사건 → 진단 → 한도 확인 → 허용 복구 → 독립 동작 검증
→ 성공: 복구 완료 기록
→ 실패: 남은 한도 안에서 다음 조치, 또는 안전 중단·운영자 전달
```

# 3. 자율성과 통제

## 3.1 자동으로 실행해도 되는 복구는 무엇인가?

| 조치 제안 | 이유 | 범위 | 선행조건 | 검증 |
|---|---|---|---|---|
| 제한된 재시도 | 일시적 실패에 대응 | 동일 사용자 요청 | 횟수·시간·비용 한도, 중복 호출 통제 | 필수 항목·응답시간 |
| 로컬 대상 재시작 | 실습 의존 서비스 복원 | 허용된 로컬 대상 하나 | 실제 중단 확인 | 사용자 경로의 기준 요청 |

## 3.2 사람의 승인이 필요한 복구는 무엇인가?

자동 중단 후 재개, 예산·정책 변경은 사람이 판단한다. 자동 예산 증액·키 변경은 금지한다. 로컬 상태 화면·로그로 운영자에게 전달한다. 담당 개인은 [미결정]이다. 미응답이면 중단 상태를 유지하고 승인으로 간주하지 않는다.

## 3.3 복구를 몇 번까지 재시도할 것인가?

명확한 일시 5xx는 2초 대기 후 추가 1회 재시도, 모의 타임아웃도 추가 1회만 허용한다. 실제 유료 타임아웃은 자동 재호출하지 않는다. 로컬 재시작은 사건당 1회·준비 대기 10초, 사건 전체는 탐지 후 90초다. 독립 검증은 별도 기준 요청 1회로 집계하며 유료 총한도에 포함한다. 모델·호출·비용 상한은 실제 호출 전 결정한다.

시도·사건·회로 상태는 원문 없는 로컬 운영 이력으로 보존한다. 구체 저장 기술은 상세 설계 대상이다. 동일 요청 병합과 시도 전 기록으로 한도를 초기화하지 않는다. 제어부 재실행 시 진행 사건은 운영자 확인 대상으로 전환한다.

## 3.4 무한 복구 루프를 어떻게 방지할 것인가?

사건별 상한·전체 시간 초과·복구 또는 검증 실패·원인 불명·실제 타임아웃 시 회로를 연다. 열린 동안 업무 생성·자동 복구는 중단한다. 최소 60초 냉각 후 운영자 재개 요청과 기준 요청 1회 통과가 있어야 닫는다. 실패하거나 미응답이면 열린 상태를 유지한다.

## 3.5 잘못된 복구를 어떻게 취소할 것인가?

| 조치 | 보존 정보 | 실패 판정 | 안전 중단 제안 | 확인 |
|---|---|---|---|---|
| 생성 재시도 | 요청 식별자·시도 이력, 원문 저장 여부는 별도 결정 | 호출·검증 실패 | 추가 호출 중단, 실패 결과 명시 | 한도 초과 없음 |
| 로컬 재시작 | 대상·직전 상태·시도 | 준비 실패·검증 실패 | 추가 재시작 중단·운영자 전달 | 대상 상태·이력 |

외부 API에 이미 전달된 요청이나 발생 비용을 롤백했다고 표시하지 않는다.

# 5. 검증

## 5.1 복구 성공을 어떤 지표로 판정할 것인가?

| 지표 | 제안 기준 | 측정 위치 | 미결정 |
|---|---|---|---|
| 동작 회복 | 쉬운 설명·핵심·질문이 정상 반환, 모드별 시간 한도·독립 요청 1회 | Verification | 없음 |
| 내용 품질 | 의미·수치·기한 보존, 없는 사실 구분, 성인 존중, 근거 피드백. 중대한 오류 시 미통과 | 가상 생활 글 5개 사람 검토 | 구체 글·검토자 |
| 실패 통제 | 한도 초과 호출 0회, 중단·전달 기록 | 사건 이력 | 없음 |
| 재현성 | 세 장애를 각 3회 동일 조건으로 반복 | 모의 실험 | 없음 |
| 비용 | 호출 수·사용량과 정한 비용 상한 준수 | 운영 기록 | 모델·예산 |

쉬운 설명과 질문이 사용자 능력을 개선한다고 단정하지 않는다. MVP는 사용 흐름과 설명 품질을 확인하며 장기 교육 효과는 별도 평가 대상이다.

## 5.2 장애 탐지부터 복구까지 걸린 시간을 어떻게 측정할 것인가?

```text
injected_at = 모의 장애 활성화 시각
detected_at = 사건 생성 시각
recovery_started_at = 첫 복구 시작 시각
recovered_at = 독립 동작 검증 통과 시각
MTTD = detected_at - injected_at
MTTR = recovered_at - injected_at
복구 처리시간 = recovered_at - recovery_started_at
```

실패 사건은 정상화 시각을 비워두고 별도 집계한다. Orchestrator가 각 역할의 사건 이벤트를 연결한다. 시각은 UTC ISO 8601 저장·Asia/Seoul 표시, 경과시간은 단조 증가 시간 계산을 PRD의 세부 제안으로 기록했다. 외부 장애 발생 시각이 불명확하면 실제 API의 MTTD·MTTR을 단정하지 않는다.

## 5.3 어떤 로그를 반드시 보존할 것인가?

**제안 항목:** 사건·요청·실험 식별자, 모의/실제 모드, 대상, 탐지·진단 근거, 시각, 복구 전략, 시도·대기, 검증 결과, 사용량, 승인·전달·최종 상태.

키·원문·사용자 답변·생성 결과는 디스크와 로그에 남기지 않는다. 글·답변·결과는 연습 중 임시 유지 후 초기화·세션 만료에 폐기한다. 세션 만료는 마지막 활동 후 30분을 PRD 세부 제안으로 둔다. 비식별 운영 로그는 로컬 7일 보존한다. 화면에 OpenAI API 전송과 가상 글 실습 원칙을 안내하며, 외부 API의 보관 조건은 실제 연동 전 별도 확인한다. API 키를 문서나 채팅에 제공할 필요는 없다.

## 5.4 최종 데모에서 어떤 장애를 주입할 것인가?

| 순서 제안 | 장애 | 재현 방법 | 예상 탐지 | 예상 복구 | 증거 |
|---|---|---|---|---|---|
| 1 | 정상 기준선 | 가상 생활 글로 실제 생성 확인 | 정상 결과 | 불필요 | 결과·내용 검토 |
| 2 | 5xx | 모의 생성 서비스 오류 | 오류 | 제한 재시도 | 시도·독립 검증 |
| 3 | 지연 | 모의 응답 지연 | 타임아웃 | 제한 재시도 | 시간·독립 검증 |
| 4 | 로컬 중단 | 허용 실습 대상만 중단 | 연결·상태 증거 | 재시작 | 상태·독립 검증 |
| 5 | 지속·반복 실패 | 모의 장애 유지 | 한도 소진 | 자동 중단·전달 | 초과 조치 없음 |

외부 OpenAI 서비스에 장애를 주입하지 않는다. 모의 실험의 성공을 실제 OpenAI 장애 복구 실측으로 보고하지 않는다. 오늘은 API 호출·장애 주입·테스트를 실행하지 않는다.

## 확인된 추가 정책과 PRD 반영

화면·첫 기능 범위와 아래 추가 정책을 기준으로 PRD 초안을 작성하는 데 사용자가 동의했다. 예산·모델은 실제 유료 호출 전에 결정할 조건으로 남긴다.

| 항목 | 제안 | 이유 |
|---|---|---|
| 실행·입력 | 로컬 웹 실행, 입력 글 최대 1,000자·연습 답변 최대 500자 | 3일 실습 범위와 긴 입력 통제 |
| 저장 | 원문·사용자 답변·생성 결과를 서버 디스크에 저장하지 않음. 연습 중에만 임시 유지하고 초기화·세션 만료 시 폐기 | 생활 글 보관 최소화. 외부 API의 보관 정책과는 별개 |
| 운영 이력 | 원문·답변·생성 결과·키를 제외한 사건·시간·횟수 기록을 로컬 7일 보존 | 장애 검토와 원문 분리 |
| 응답·복구 한도 | 생성 시도당 30초, 명확한 일시 5xx만 2초 대기 후 추가 1회 재시도. 실제 유료 호출의 타임아웃은 자동 재호출 없이 상태 안내 | 비용·중복 호출 통제. 수치는 실측 전 목표 |
| 중단 복구 | 중단 확인된 허용 로컬 대상만 사건당 재시작 1회, 준비 대기 최대 10초 | 외부 OpenAI 서비스 조작과 구분 |
| 전체·회로 | 탐지 후 전체 90초 한도, 복구·독립 검증 실패 또는 원인 불명 시 회로 열림. 60초 냉각 후 운영자가 재개 요청하고 기준 요청 검증 | 무한 반복 방지 |
| 모의 검증 | 모의 요청은 2초 한도·실패 시 추가 1회, 세 장애 각 3회 반복. 독립 기준 요청 1회 통과, 검증 실패 시 추가 유료 재생성 금지 | 반복 실험 비용 없이 동작 회복 확인 |
| 실제 품질 확인 | 가상 생활 글 5개에서 의미·수치·기한 보존, 원문 밖 사실 구분, 쉬운 표현·성인 존중, 질문·힌트·근거 피드백을 사람이 검토. 사실·행동을 바꾸는 오류가 있으면 미통과 | 동작 성공과 내용 정확성 분리 |
| 예산·모델 | PRD에서는 미결정 유지. 실제 유료 호출 전에 모델·호출 상한·비용 상한 확정 | 예산을 임의 결정하지 않음 |

실제 API 검증용 기준 요청도 유료 호출 상한에 포함하며 숨은 반복 호출을 만들지 않는다. 사용자가 고른 모델과 실제 응답시간을 확인한 뒤 시간 기준 변경이 필요하면 문서에 근거를 기록한다. 간단한 설명 화면에는 입력 글이 OpenAI API로 전송됨을 알리고, 실습 입력은 가상 글로 제한하는 방안을 제안한다.
