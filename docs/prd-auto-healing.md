## 2. 프로젝트 개요

이해하기 어려운 생활 글을 만난 성인이 쉬운 설명과 핵심을 확인하고, 짧은 질문·힌트를 통해 자신의 생각을 정리하도록 돕는다. 특정 진단이 있어야 사용할 수 있는 서비스로 제한하지 않는다.

> 성인 사용자가 생활 글을 입력하면, 서비스는 OpenAI API로 쉬운 설명·핵심 정리·생각 질문을 제공하고, 사용자의 답변에 원문 근거를 연결한 피드백을 제공한다.

```text
성인 사용자 → 생활 글 입력·도움 요청 → 글 이해·생각 정리 서비스
→ 설명 생성 의존 서비스 → OpenAI API
→ 쉬운 설명·핵심·질문 → 선택적 힌트 → 답변 피드백 한 번
```

실제 설명 생성에는 OpenAI API를 사용한다. 오류·지연·중단 실험은 로컬 모의 생성 서비스로 재현한다. 두 모드를 구분하여 모의 실험 결과를 실제 외부 API 장애 복구 성과로 표현하지 않는다.

## 3. 문제 정의

낯선 단어와 복잡한 문장은 글의 핵심, 조건, 해야 할 일을 파악하기 어렵게 만들 수 있다. 쉬운 설명에 더해 원문에서 확인할 수 있는 것과 없는 것을 구분하고, 사용자가 직접 생각할 기회가 필요하다.

사용자는 자신의 어려움을 바탕으로 이 주제를 제안했다. 해당 경험만으로 지능·진단·사고 능력을 판단하지 않는다. 서비스의 목표는 이해와 생각 정리를 돕는 것이며, 치료 효과나 인지 능력 향상을 보장하지 않는다.

생성 의존 서비스가 실패하면 설명과 연습이 중단된다. 무분별한 재요청은 대기와 비용을 늘릴 수 있어 제한된 복구와 안전한 중단이 필요하다. 기존 운영 시스템·수동 대응 시간은 확인되지 않았으므로 개선율을 주장하지 않는다.

## 4. 사용자와 이해관계자

| 대상 | 필요한 도움·책임 |
|---|---|
| 성인 사용자 | 안내문·공지·문자 등 생활 글 이해, 선택적으로 질문 연습 |
| 실습 운영자 | 사건·비용 상태 확인, 중단 원인 조사, 재개 판단 |
| 개발 담당자 | 최소 기능 구현과 격리된 장애 재현, 인원 미정 |
| 품질 검토자 | 기준 글에 대한 의미 보존·쉬운 표현·피드백 검토, 담당자 미정 |

아동·청소년 확장은 후속 검토 대상이다. 성인을 존중하는 말투를 사용하며 틀렸다는 낙인·지능 점수·능력 등급을 제공하지 않는다.

## 5. 목표와 성공 기준

| 목표 | 판정 기준 |
|---|---|
| 핵심 사용 흐름 | 글 하나에서 설명·핵심·질문 하나를 확인하고 힌트 및 답변 피드백 한 번까지 사용 가능 |
| 입력 범위 통제 | 생활 글 최대 1,000자, 답변 최대 500자. 빈 입력·초과 입력은 외부 호출 전에 안내 |
| 내용 품질 | 가상 생활 글 5개에서 의미·수치·기한 보존, 원문 밖 정보 구분, 성인 존중, 질문·힌트·근거 피드백을 사람이 검토 |
| 중대한 설명 오류 방지 | 사실·행동을 바꾸는 오류가 하나라도 발견되면 해당 품질 검증 미통과 |
| 장애 재현 | 모의 5xx·타임아웃·로컬 중단을 각 3회 반복하고 모든 복구 가능한 실험에서 독립 동작 검증 통과 |
| 복구 통제 | 사건별 한도 초과 조치 0회. 미복구 시 중단·회로 열림·운영자 확인 정보 존재 |
| 호출·시간 제한 | 실제 생성 시도 30초, 일시 5xx 추가 재시도 1회, 탐지 후 사건 처리 90초 한도 |
| 기록 보호 | 원문·답변·생성 결과·키의 서버 디스크 및 로그 저장 0건 |

5개 기준 글 검토는 실습 품질 평가이며 전체 성인에 대한 효과나 모든 입력의 정확성을 입증하지 않는다. 이해하기 쉬운지에 대한 사용자의 의견도 기록하되 교육 효과 점수로 해석하지 않는다.

## 7. 정상 서비스 시나리오

1. 사용자가 로컬의 간단한 웹 화면을 연다. 글이 OpenAI API로 전송됨과 실습에는 가상 글을 사용할 것을 알린다.
2. 최대 1,000자의 글을 입력하고 도움을 요청한다. 빈 글과 초과 입력은 호출 전에 안내한다.
3. 쉬운 설명·핵심 정리·생각 질문 하나를 구분해 표시한다. 사용자가 요청하면 힌트를 보여준다.
4. 사용자는 연습을 건너뛰거나 최대 500자의 답변을 입력한다.
5. 답변에 대한 피드백 한 번을 보여준다. 맞고 틀림만 표시하기보다 원문의 근거와 생각해 볼 부분을 설명한다.
6. 새 글로 시작하면 이전 글·답변·결과를 초기화한다.

문맥이 부족하면 없는 내용을 만들어 설명하지 않고 부족한 정보를 알린다. 보충 정보가 필요할 경우 새 글 입력으로 안내하며 장기 대화로 확장하지 않는다. 원문과 예시·추측·일반 설명은 구분한다.

힌트는 최초 생성 결과에 포함하여 버튼으로 펼치는 방식을 기준으로 한다. 힌트 클릭은 추가 유료 호출을 만들지 않는다. 정상 흐름의 유료 생성은 최초 설명과 답변 피드백에 각각 최대 1회이며, 재시도·독립 검증 호출은 별도로 기록하고 총한도에 포함한다.

## 8. 장애 시나리오

| 장애 | 위치·관찰 신호 | 안전한 재현 | 영향 |
|---|---|---|---|
| 일시 5xx | 모의 생성 서비스 오류 응답 | 실험의 최초 요청 1회만 오류 후 정상 응답 | 설명 요청 실패 |
| 타임아웃 | 모의 응답의 2초 제한 초과 | 최초 모의 요청에 3초 지연 후 정상 동작 | 기다림·결과 미수신 |
| 로컬 생성 서비스 중단 | 연결 실패와 지정 대상 중단 상태 | 실습용 모의 대상만 중단 | 생성 경로 연결 불가 |
| 지속 장애 | 추가 시도·검증도 실패 | 모의 오류 모드 유지 | 자동 복구 불가 |
| 원인 불명 | 연결 실패이나 대상 실행 중·상태 미확인 | 실습용 연결 실패 조건 | 중단으로 오진할 위험 |

오류 모드 종료는 미리 정한 일시 장애 조건이다. Recovery가 장애 스위치를 끄고 복구했다고 보고하지 않는다. 외부 API에 실제 장애를 유발하지 않는다.

## 9. 멀티 에이전트 구성

역할은 책임의 구분이며 사람 수·별도 프로세스 수·LLM 수를 의미하지 않는다. 생성 기능은 모델을 사용하고, 탐지·한도·상태 전이는 규칙으로 처리한다.

### Monitor

- 책임: 진행 중 요청의 오류·시간·연결 이상 관찰.
- 입력: 생성 경로 응답과 경과시간.
- 출력: 사건 식별자·대상·탐지 시각·증거.
- 정보·허용 행동: 응답 메타데이터 읽기·사건 생성. 주기적 유료 생성으로 상태를 점검하지 않음.
- 금지 행동: 복구·정책 변경·원문 로그 저장.
- 실패 시 행동: 관찰 실패를 기록하고 Orchestrator에 전달.

### Diagnosis

- 책임: 관찰된 실패를 일시 오류·타임아웃·확인된 로컬 중단·원인 불명으로 구분.
- 입력: 사건·응답 증거·허용 대상 실행 상태.
- 출력: 분류·근거·허용 복구 방향.
- 정보·허용 행동: 사건·상태 조회.
- 금지 행동: 복구 직접 실행, 연결 실패만으로 중단 단정.
- 실패 시 행동: 원인 불명으로 자동 변경 중단 요청.

### Recovery

- 책임: 허용 정책·잔여 한도 안에서 조치.
- 입력: 진단·남은 횟수·시간·실제 호출 허용 상태.
- 출력: 대상·시도·대기·결과.
- 정보·허용 행동: 제한된 호출, 중단 확인된 로컬 대상의 재시작.
- 금지 행동: 외부 인프라 조작, 입력 변조, 임의 명령, 한도 초기화.
- 실패 시 행동: 결과 기록 후 제어 반환. 독자적으로 다음 정책을 만들지 않음.

### Verification

- 책임: Recovery의 실행 결과와 별도로 사용자 경로 동작 확인.
- 입력: 기준 글·필수 항목·현재 모드.
- 출력: 독립 통과·실패와 근거.
- 정보·허용 행동: 기준 요청 1회, 결과 항목·시간 확인.
- 금지 행동: Recovery 보고만으로 성공 선언, 검증 실패 후 자동 유료 재생성 반복.
- 실패 시 행동: 미복구로 판정. 내용 정확성은 별도 사람 검토에 맡김.

### Orchestrator

- 책임: 역할 순서, 사건·한도·회로·최종 상태 관리.
- 입력: 사건과 각 역할 결과.
- 출력: 상태 전이·중단·운영자 확인 요청.
- 정보·허용 행동: 역할 호출, 동일 요청 사건 병합, 시도 기록.
- 금지 행동: 직접 복구 도구 조작, 한도·예산 우회.
- 실패 시 행동: 추가 조치 중단, 확인 필요한 사건으로 유지.

### Notification

- 책임: 사용자에게 실패·대기·재시도 가능 상태를 알리고 운영자에게 사건 근거 표시.
- 입력: 상태·비식별 이력.
- 출력: 간단한 상태 화면·로컬 로그.
- 정보·허용 행동: 결과 표시.
- 금지 행동: 원문·키 공개, 자동 정책 변경, 허가되지 않은 외부 전송.
- 실패 시 행동: 표시 실패 기록, 조회 가능한 사건 상태 유지.

## 10. 에이전트 협업 흐름

```text
사용자 요청 → 생성 시도 → 오류·시간 관찰 → 사건 생성·병합 → 진단
→ 횟수·시간·호출 허용 확인 → 제한된 복구 → 독립 기준 요청
  ├─ 통과: 복구 완료 기록, 사용자 결과 또는 재요청 안내
  └─ 실패·한도 소진·원인 불명: 회로 열기, 추가 자동 조치 중단, 운영자 전달
```

동일 사용자 요청은 하나의 요청 식별자로 연결하고 같은 대상의 활성 복구 사건은 하나로 병합한다. 버튼 반복 클릭으로 유료 중복 요청이나 새 복구 한도를 만들지 않는다. 기준 검증 결과를 원래 사용자의 설명으로 대신 표시하지 않는다. 로컬 재시작으로 원래 요청이 사라졌다면 복구 완료와 재요청 필요를 구분한다.

|---|---|---|---|---|---|---|---|
| 명확한 일시 5xx | 해당 경로의 5xx 응답 | 2초 대기 후 1회 재시도 | 실패 시 회로 열기 | 최초 포함 생성 최대 2회 | 사전 정책·예산 내 자동 | 추가 호출 중단, 발생 비용 취소 주장 금지 | 별도 기준 요청 1회 |
| 모의 타임아웃 | 모의 요청 2초 초과 | 2초 대기 후 모의 재시도 1회 | 실패 시 회로 열기 | 최초 포함 모의 생성 최대 2회 | 정책 내 자동 | 늦은 결과의 중복 반영 방지 | 모의 기준 요청 1회, 2초 한도 |
| 실제 생성 타임아웃 | 실제 시도 30초 초과 | 자동 재호출 없음 | 상태 안내·회로 열기 | 실제 시도 1회 | 조사·재개는 사람 | 결과·비용 상태 불확실성 기록 | 운영자 재개 시 별도 기준 요청 |
| 로컬 중단 | 연결 실패와 허용 대상 중단 확인 | 지정 대상 재시작 1회 | 준비 대기 최대 10초 | 재시작 1회 | 정책 내 자동 | 실패 시 추가 재시작 중단 | 사용자 경로 기준 요청 1회 |
| 원인 불명·지속 실패 | 분류 불가·시도/검증 실패 | 자동 변경 중단 | 운영자 확인 | 추가 시도 0회 | 재개는 사람 | 회로 열림 유지 | 재개 조건 충족 확인 |

독립 검증은 별도 호출이며 재시도 횟수와 분리해 기록한다. 실제 5xx 사건의 허용 호출은 최초 1회·복구 재시도 1회·기준 검증 최대 1회다. 정상 요청에 추가 검증 호출을 항상 붙이지 않는다. 힌트 펼치기는 호출하지 않는다. 자동 재시도는 내부 라이브러리나 다른 계층을 포함해 총합 1회를 넘지 않아야 한다.

- 실제 시도·실제 기준 검증은 각각 30초 한도, 모의 시도·검증은 각각 2초 한도다. 이 기준은 선택할 모델의 보장 성능이 아니라 실습 목표다.
- 사건 전체는 탐지 후 90초 한도다. 만료 시 새 조치를 시작하지 않고 진행 중 동작의 최종 상태를 기록한다.
- 복구 한도 소진·독립 검증 실패·원인 불명·전체 시간 초과·실제 타임아웃 시 해당 생성 경로의 회로를 연다.
- 열린 동안 신규 업무 생성·자동 복구 호출을 중단하고 상태만 보여준다. 최소 60초 냉각 후 운영자가 명시적으로 재개를 요청해야 한다.
- 재개 요청에는 기준 검증 1회만 허용한다. 통과하면 닫고 실패하면 열린 상태를 유지한다. 실제 기준 요청도 사전 유료 호출 상한에 포함한다.
- 인증·권한·예산·한도 관련 실패는 일시 5xx 정책으로 무조건 재시도하지 않는다. 구체 공급자 오류 분류는 구현 전 공식 문서에 맞춰 확인한다.
- 상태·시도·회로는 비식별 운영 이력으로 보존한다. 제어부 재실행 시 진행 중 사건은 자동 조치를 재개하지 않고 사람의 확인 대상으로 전환한다.

## 12. 자율성과 Human-in-the-loop

| 범주 | 행동 |
|---|---|
| 자동 가능 | 오류 관찰·분류, 허용된 일시 오류 재시도, 확인된 로컬 대상 재시작, 독립 검증, 상태 기록 |
| 사람 판단 필요 | 회로 재개, 원인 불명 조사, 모델·호출·비용 상한 확정, 정책 변경, 내용 품질 판단 |
| 자동 금지 | 예산 증액·결제·키 변경, 외부 인프라 조작, 임의 명령, 원문·답변 장기 저장, 무한 재호출 |

운영자는 로컬 상태 화면과 원문 없는 로그로 사건을 확인한다. 재개 요청이 없으면 자동 승인하지 않고 열린 상태를 유지한다. 모델·예산·호출 상한 미설정 상태에서는 실제 유료 호출을 활성화하지 않는다. 이는 문서 검토 진행을 막지 않으며 후속 실행의 선행조건이다.

## 13. 기능 요구사항

### FR-001 입력과 새 글 시작

- 설명: 간단한 웹 화면에서 생활 글을 입력한다.
- 입력: 글 최대 1,000자.
- 기대 동작: 빈 입력·초과를 확인한 뒤 생성 요청. 새 글 시작 시 이전 임시 상태 폐기.
- 예외 상황: 잘못된 입력·중복 제출·열린 회로는 추가 생성하지 않고 안내.
- 인수조건: 제한 위반의 외부 호출 0회, 동일 제출의 중복 유료 호출 0회.

### FR-002 쉬운 설명과 핵심 정리

- 설명: 원문의 뜻을 보존하는 쉬운 설명을 제공한다.
- 입력: 생활 글.
- 기대 동작: 쉬운 설명·핵심·질문 1개·힌트 제공. 원문 밖 예시와 불확실성 구분.
- 예외 상황: 문맥 부족은 부족하다고 표시하며 사실을 추가해 채우지 않음. 응답 누락은 정상 결과로 표시하지 않음.
- 인수조건: 필수 항목이 구분되고 기준 글의 수치·기한·조건을 바꾸지 않는다.

### FR-003 생각 질문과 힌트

- 설명: 사용자가 직접 정리할 기회를 제공한다.
- 입력: 생성 결과와 힌트 표시 선택.
- 기대 동작: 질문 하나와 선택적 힌트. 연습을 건너뛸 수 있음.
- 예외 상황: 힌트 클릭에 추가 생성하지 않음.
- 인수조건: 힌트 펼치기·건너뛰기에 유료 호출 0회, 답변 강요·능력 점수 없음.

### FR-004 답변 피드백

- 설명: 사용자 답변을 원문 근거와 연결해 설명한다.
- 입력: 원문·질문·최대 500자의 답변, 세션 내 임시 사용.
- 기대 동작: 피드백 한 번 제공, 근거와 보완할 생각을 존중하는 말투로 표시.
- 예외 상황: 빈 답변·초과 입력은 호출 전 안내, 실패는 사용자 능력 문제로 표현하지 않음.
- 인수조건: 기준 글에서 근거를 연결하며 원문에 없는 결론을 정답으로 강요하지 않는다.

### FR-005 사건 관찰과 진단

- 설명: 실제/모의 모드의 장애를 근거와 함께 분류한다.
- 입력: 응답·시간·대상 상태.
- 기대 동작: 사건 생성·병합, 진단 기록.
- 예외 상황: 로컬 상태 불명은 원인 불명으로 처리.
- 인수조건: 연결 실패만으로 재시작 0회, 유료 주기 점검 0회, 사건별 모드 식별 가능.

### FR-006 제한된 복구와 회로 관리

- 설명: 11절의 횟수·대기·시간·재개 정책을 적용한다.
- 입력: 사건·남은 한도·회로·실제 호출 허용 상태.
- 기대 동작: 조치 전 시도 기록, 한도 실패 시 중단·운영자 표시.
- 예외 상황: 저장 실패·전체 시간 초과 시 새 자동 조치를 시작하지 않음.
- 인수조건: 각 정책 한도 초과 0회, 실제 타임아웃 자동 재호출 0회, 냉각·운영자 요청 없이 회로 재개 0회.

### FR-007 독립 동작 검증

- 설명: 복구 조치와 별개로 기준 글의 사용자 경로를 확인한다.
- 입력: 고정 가상 기준 글·필수 출력 항목.
- 기대 동작: 기준 요청 1회, 모드별 시간·항목 확인.
- 예외 상황: 실패 시 추가 유료 재생성 대신 회로 열림 유지.
- 인수조건: Recovery의 성공 보고만으로 사건 종료 0회. 기준 결과를 사용자 원문 결과로 대체하지 않음.

### FR-008 운영 상태·이력

- 설명: 원문 없이 사건·조치·검증·재개 상태를 확인한다.
- 입력: 사건 ID 또는 현재 상태 조회.
- 기대 동작: 사용자에게 짧은 실패 안내, 운영자에게 근거·시도·다음 판단 표시.
- 예외 상황: 키·원문이 포함될 수 있는 공급자 오류 본문은 그대로 저장·노출하지 않음.
- 인수조건: 사건별 이력 연결, 원문·답변·생성 결과·키의 로그 저장 0건.

### FR-009 실습 모드와 호출 한도

- 설명: 모의 장애 실험과 실제 생성 확인을 구분한다.
- 입력: 운영자 모드 선택, 실제 호출 활성화 조건.
- 기대 동작: 모의 요청은 외부 API를 호출하지 않음. 실제 호출은 확정된 모델·횟수·비용 범위에서만 수행.
- 예외 상황: 상한 미정·소진·비용 판단 불가는 실제 호출 차단.
- 인수조건: 세 모의 장애에서 외부 API 호출 0회, 실제 기준 검증·재시도도 호출 총합에 포함.

## 14. 비기능 요구사항

- NFR-001 이해 용이성: 설명·핵심·질문을 구분하고 쉬운 표현을 사용한다. 긴 문장을 나누되 의미를 바꾸지 않는다.
- NFR-002 존중: 성인에게 맞는 말투, 건너뛰기·힌트 선택, 평가 낙인·진단 단정 금지.
- NFR-003 개인정보: 서버 디스크에 원문·답변·결과를 저장하지 않는다. 전송 안내와 가상 글 실습 원칙을 제공한다.
- NFR-004 신뢰성: 복구와 검증 책임 분리, 정해진 한도와 열린 회로 준수, 공급자 응답 내용의 임의 조작 금지.
- NFR-005 관측 가능성: 사건·요청·실험 식별자로 모드·시간·조치·최종 상태를 추적한다.
- NFR-006 비용 통제: 전체 호출 계층의 재시도·검증을 집계하고 자동 비용 증액하지 않는다. 정확한 비용 추정 방식은 선택 모델 확인 후 상세화한다.
- NFR-007 실행 범위: 로컬 웹 실습을 기준으로 한다. Python·FastAPI·Docker 사용 경험을 활용할 수 있으나 구체 버전과 구성은 후속 설계 대상이다. AWS 배포는 제외한다.
- NFR-008 성능 범위: 단일 사용자 실습에서 실제 시도 30초·모의 시도 2초 목표를 검토한다. 동시 사용자 부하 보장은 비목표다.

## 15. 데이터와 로그 요구사항

원문·답변·생성 결과는 연습 중 임시로만 유지한다. 새 글 시작·초기화·세션 만료 때 폐기한다. 문서에서 제안하는 임시 세션 만료는 마지막 활동 후 30분이며 이 시간은 최종 검토 대상이다. 웹 새로고침·프로세스 재시작 후 이어하기는 보장하지 않는다. 이 정책은 서비스 자체 저장 기준이며 외부 API의 보관 정책을 보장한다는 뜻이 아니다. 외부 전송·보관 조건은 실제 사용 전 확인한다.

운영 로그는 로컬 7일 보존 후 제거한다. 필수 항목은 사건·요청·실험 ID, 실제/모의 모드, 대상, 주입·탐지·복구 시작·검증 완료 시각, 정제된 오류 분류, 진단 근거, 전략, 시도·대기·결과, 검증 항목·시간, 회로 상태, 재개 요청·결과, 사용량·호출수, 최종 상태다. 원문·답변·생성 결과·키·원문을 포함할 수 있는 오류 본문은 저장하지 않는다.

시각은 UTC ISO 8601 저장과 Asia/Seoul 화면 표시를 제안한다. 경과시간은 단조 증가 시간으로 계산한다. 이 표기 방식은 사용자 최종 문서 검토 대상이며 실제 측정은 아직 하지 않았다. 로그 저장·사건 통제를 위한 구체 기술은 상세 설계에 맡긴다.

| 재개·제어부 재실행 | 냉각 60초·명시적 요청·검증 없이 닫힘 없음, 진행 사건 자동 재개 없음 |
| 로그·초기화 | 원문 없는 이력과 임시 글 폐기 확인 |

모의 복구 실험은 각 회차마다 정상 상태에서 시작하고 대상과 기대 출력을 고정한다. 동작 검증은 필수 항목과 시간, 내용 품질은 의미·근거·표현을 확인한다. 품질 검토의 통과를 임상·교육 효과로 표현하지 않는다.

- MTTD = 사건 생성 시각 − 모의 장애 주입 시각.
- MTTR = 독립 검증 통과 시각 − 모의 장애 주입 시각.
- 복구 처리시간 = 독립 검증 통과 시각 − 첫 복구 시작 시각.
- 성공률 = 독립 검증 통과 건수 ÷ 복구 가능 조건 실험 건수. 실패·지속 장애는 별도 집계.
- 실제 외부 장애는 발생 시각을 알 수 없으면 MTTD·MTTR로 단정하지 않고 요청 경과시간·탐지 후 처리시간만 보고한다.

각 사건의 값과 평균을 함께 기록하고 미복구 사건의 정상화 시각은 비워둔다. 최초 생성은 사건 없이 정상 반환했다면 복구 성공 건수로 집계하지 않는다.

## 17. 3일 MVP 포함·제외 범위

포함 범위는 성인용 짧은 생활 글 하나의 설명·질문·피드백 흐름, 실제 OpenAI 생성 연동, 모의 의존 서비스의 세 장애 복구, 회로와 상태·시간 기록, 독립 검증이다.

제외 범위는 6절을 따른다. 개발 인원은 미정이며 역할별로 사람을 지정하지 않는다. 인원이 정해지면 최소 범위의 실현 가능성을 재평가한다. 오늘의 산출물은 워크시트와 PRD·검토 기록이며 개발 작업목록·코드·테스트·배포 파일은 생성·수정하지 않는다.

## 18. 위험과 대응

| 모의 성과와 실제 성과 혼동 | 효과 과장 | 모드별 결과·기능 검증·내용 품질 분리 |
| 인원·환경 미확인 | 일정 지연 | 짧은 입력·질문 하나·피드백 한 번 유지, 후속 착수 전 확인 |

## 19. 미결정 사항

| ID | 항목 | 필요한 결정 | 책임자 | 기한·영향 |
|---|---|---|---|---|
| U-001 | 모델·호출·비용 상한 | 이용 모델, 한 번·실습 전체의 호출/비용 기준 | 사용자·개발 담당자 | 실제 유료 호출 전 필수, 문서 검토는 가능 |
| U-002 | 개발 인원·경험·환경 | 인원과 로컬 실행 가능 여부 | 사용자·개발 담당자 | 후속 구현 착수 전, 3일 가능성 재평가 |
| U-003 | 기준 글·품질 검토자 | 생활 안내·공지 등 가상 글 5개와 근거·평가 담당 | 사용자·개발 담당자 | 후속 검증 설계 전 |

모델·요금·계정 접근 권한·외부 보관 정책의 최신 사실을 이 문서에서 확정하지 않는다. 특정 모델·가격·SDK·API 호출 형식은 정하지 않았으며, 구현 전 공식 문서를 확인한다. 30분 세션 만료·UTC 저장 표기는 이번 초안의 세부 제안으로 최종 검토에 포함한다.

### 자체 검토 결과

- 충족: 사용자·정상 결과·서비스 경계, 세 장애와 모의 재현, 역할별 책임·권한·실패 처리, 독립 검증, 시도·시간·회로·재개, 개인정보·호출 한도, 품질 검토, 포함·제외 범위.
- 보완: 모델·비용·실행환경·기준 글은 후속 실행 전 해결한다. 실제 응답시간·정확성·복구 성공률은 아직 검증하지 않았다.
- 범위 초과 위험: 자유 대화·진단·파일·클라우드·장기 이력을 추가하지 않는다. 비용이 드는 별도 LLM 모니터링을 두지 않는다.
- 승인 권고: 문서 승인 가능. 사용자는 초안 세부 제안과 남은 선행조건을 검토하며, 승인으로 유료 실행을 허가한 것으로 간주하지 않는다.
